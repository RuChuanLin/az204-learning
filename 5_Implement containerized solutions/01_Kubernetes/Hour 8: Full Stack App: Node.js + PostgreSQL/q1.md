can I restart a kube object without delete it ? I want to slightly change some parameter in the yaml file

---

Yes! You can absolutely update a Kubernetes object **without deleting it** — this is actually the recommended way to manage K8s resources.

There are two main ways to do this:

---

## ✅ Option 1: `kubectl apply -f yourfile.yaml` (Declarative)

If you change a field in your YAML (e.g., environment variable, resource limit, image version, etc.), just run:

```bash
kubectl apply -f deployment.yaml
```

Kubernetes will:

* Compare your updated file with the current object
* Apply only the changes
* Automatically **restart the Pod(s)** if needed (e.g., env var or image changes)

> 🧠 This is the *preferred*, safe way to "restart with changes" — no deletion needed.

---

## ✅ Option 2: Manual Rollout Restart (Imperative)

If your YAML changes **don’t trigger a Pod restart** (like changing labels or annotations), but you still want to restart the Pods:

```bash
kubectl rollout restart deployment <deployment-name>
```

This forces a **rolling restart** of the deployment, recreating Pods with the same config.

✅ Useful when:

* You changed a ConfigMap or Secret (and didn’t mount it as a volume)
* You want to force a refresh without touching your YAML

---

## ⛔ Avoid This: `delete` + `apply`

Although it works, it’s not ideal:

```bash
kubectl delete -f deployment.yaml
kubectl apply -f deployment.yaml
```

This causes:

* Downtime
* Loss of status/history (e.g., rollout info)

Only use this if you're fully resetting something (like a failed `Job` or `Pod` with `restartPolicy: Never`).

---

### 🔍 Example: You changed CPU limits

```yaml
resources:
  requests:
    cpu: "100m"
  limits:
    cpu: "250m"
```

→ Just save and re-run:

```bash
kubectl apply -f deployment.yaml
```

Pods will be updated seamlessly.
